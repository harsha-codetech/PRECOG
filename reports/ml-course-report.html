1. Problem Statement

Digital wellbeing tools currently operate on aggregate screen-time counts and fixed population thresholds. They cannot distinguish a deliberate long session from a compulsive one, and they apply the same threshold to all users despite large individual differences in phone-use behaviour.

PRECOG (Personalized Recognition and Estimation of Compulsive Online-scrolling Gestures) addresses a narrow but underexplored gap: using scroll kinematics to build a per-user behavioural baseline, and detecting when a session deviates from that personal baseline. The research questions are:

  • H1: Are scroll kinematics individually distinctive enough to support personalised modelling?
  • H2: How quickly does a personal baseline converge, and does it remain stable over time?
  • H3: Does a personalised model reduce false positives compared to a global threshold?
Important scope boundary. No public dataset labels naturalistic scroll sessions as compulsive. PRECOG claims personalisation learnability, stability, and characterisation of deviation — not compulsive-use detection. That requires future labelled data.

2. Datasets and Data Pipeline

2.1 Datasets used

DatasetRoleSize after extractionNotes
HMOG (Buriro et al. 2017)Primary (H1, H2, H3)39,556 gestures · 99 subjectsLab reading task; posture labels (sit/walk)
FETA (Ferreira et al. 2022)Replication (H1, H2)288,124 scroll · 138 subjects · 30+ daysNaturalistic in-the-wild; no posture labels
Synthetic cohortMechanism testbed472,842 gestures · 200 usersParameters fitted from FETA; ground-truth anomaly labels

HMOG provides per-event touch data with session metadata (posture, task). The extraction pipeline segments events into strokes using DOWN/MOVE/UP event sequences and computes 28 kinematic features per stroke.

FETA is a 30-day longitudinal dataset of naturalistic scroll and swipe sessions. Only scroll gestures are used (the swipe contrast was withdrawn; see §5).

2.2 Preprocessing

  • Contiguous enrollment: the first N gestures from each subject's earliest sessions are used for baseline enrollment. No random sampling — this follows the temporal order of real deployment (FETA pitfall P3).
  • Feature standardisation: robust z-score using median and MAD within each user.
  • Non-finite handling: pd.to_numeric(errors='coerce') on all feature columns; rows with non-finite values dropped before modeling.
  • Direction features excluded from supervised models: direction_flag, average_direction, direction_end_to_end are gesture-type proxies (scroll 99.2% vertical, swipe 1.7%), not behavioural features.

SHAP analysis (EXP-007) revealed the most discriminative features for posture detection: mid_stroke_area (SHAP 0.680), duration_ms (0.448), inter_scroll_ms (0.430). These three together explain the practical construct of "how this user scrolls."

4. Models and Evaluation Protocol

4.1 Evaluation design

Subject-wise GroupKFold CV is mandatory. Standard random splits allow gestures from the same user to appear in both train and test, inflating performance estimates. All experiments use GroupKFold on subject IDs, with contiguous enrollment always preceding test data.
  • Primary metric: PR-AUC (area under precision-recall curve). The walk-vs-sit contrast is imbalanced (60% walk), making PR-AUC more informative than ROC-AUC.
  • Significance: Wilcoxon signed-rank test on per-subject scores; Cliff's δ as effect size.
  • Baseline: Chance PR-AUC = class prevalence (0.61 for sit→walk).

5. Experiments

5.1 Contrast validity — a critical correction

Two contrasts were withdrawn mid-project after SHAP analysis.
Reading→map (EXP-004): direction features show 98% vs 48% vertical split — models were detecting gesture direction, not behaviour.
Scroll→swipe (EXP-005c): 99.2% vs 1.7% vertical — PR-AUC 1.000, trivially separable.
Only sit→walk remains valid (same task, same gesture type, same recording context).

This was caught because EXP-007 XGBoost hit PR-AUC 1.000 and SHAP was immediately inspected. Rule added to project protocol: "a model that performs perfectly is investigated, not celebrated."

H1 is replicated across two independent datasets. The key finding is not the mean accuracy but the 0–85% spread: some users have highly distinctive signatures, others do not, and any deployed system must account for this heterogeneity.

H2 — Baseline convergence SUPPORTED WITH QUALIFICATION

HMOG: median subject reaches ρ≥0.95 at n=80 gestures (~2 sessions). FETA full-span curve never reaches 0.95 — but window-matched FETA reaches ρ=0.969 at n=200. The n=80 finding holds for short-window deployment. Longitudinal use requires adaptation because drift is +12%/30 days (Spearman ρ=+0.041, p=1.3e-104).

7. Ablations and New Experiments

7.1 PCA Component Sweep (EXP-011)

Swept k=2…25 components. PR-AUC is nearly flat above k=5 (variance 0.579–0.610). k=8 covers 85.1% of variance and sits in the flat plateau — the choice is robust to ±4 components in either direction.

7.2 Feature Selection by SHAP (EXP-012)

Top-k SHAP features vs full set. Full set (28 features, PR-AUC 0.549) outperforms all subsets. Top-3 (0.544) loses only 0.005. Recommendation: use the full set; if privacy-constrained, top-5 captures 99% of performance.

7.3 Per-User GMM (EXP-013)

Replacing Mahalanobis with a 2-component GMM per user reduces median FPR at 80% sensitivity from 0.810 to 0.746 on HMOG (real data), and from 0.455 to 0.328 on synthetic person-relative anomalies. This is the strongest improvement found in this project and motivates a SPEC update.

7.4 Session-Level Aggregation (EXP-014)

Mean-score aggregation over non-overlapping windows of 1–40 gestures. PR-AUC flat across all window sizes (0.574–0.587). The sit→walk contrast has ~60% walk prevalence throughout — there is no temporal concentration for aggregation to exploit. The PRECOG use case (episodic compulsive sessions) would benefit from aggregation, but requires naturalistic labelled data to test.

8. Conclusion

What stands

  • H1 is replicated: scroll kinematics are individually distinctive. The 0–85% per-user accuracy spread is the strongest finding — it shows both the opportunity (some users have rich signatures) and the risk (many do not).
  • Drift is confirmed: +12% deviation growth over 30 days, monotonic, highly significant. Any deployed baseline requires adaptation.
  • The H3 null is settled: three independent methods and two detectors all agree. Personalization as implemented does not reduce FPR for posture-change detection. The mechanistic reason is identified (population-consistent deviation).
  • GMM-2 density estimation is a genuine improvement: the strongest positive result, not anticipated at project start, and directly actionable.

What does not stand

  • H3 positive claim — collapsed under better detectors (three times, three methods).
  • Task contrasts (reading→map, scroll→swipe) — withdrawn; gesture direction confound.
  • EXP-008 sign flip magnitude — largely an artifact of the weaker global baseline.

Honest limits

  • No compulsive-use labels in any dataset — the ultimate deployment signal is unavailable.
  • One valid real contrast (sit→walk) is a posture-change proxy, not a compulsive-use proxy.
  • Per-user spread means ~20–30% of users may have signatures too weak to support reliable detection.

Lessons for the ML track

  1. A model that performs perfectly on a contrast is a bug, not a result.
  2. Every null obtained with a weak instrument is provisional — re-test with the best method available.
  3. Subject-wise CV is not optional for person-dependent behaviour data.
  4. The NB–LogR gap is informative: it measures feature correlation structure.
  5. Density model choice (single-Gaussian vs GMM) can matter more than model architecture.
